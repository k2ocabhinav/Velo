I've read the security-critical code end to end. Here's my review.

## Summary

The backend has a solid skeleton — stateless JWT, method-level `@PreAuthorize` on admin/payout/earnings surfaces, tenant filters on most ride/identity lookups, and a deliberate httpOnly-cookie BFF on the frontend. But the security posture is undermined by a handful of serious, verified holes: an unauthenticated privilege-escalation endpoint, password hashes returned by an admin API, a dev JWT secret/demo-credentials shipped to prod, reset tokens written to logs, and a second copy of the JWT in `sessionStorage` that nullifies the httpOnly design. Multi-tenant isolation is correct in the ride path but patchy in admin/promo/scheduled paths. Overall: **not production-safe yet**; the open "Security & production readiness" checklist in `PROGRESS.md` is real and blocking.

## Gaps (docs vs code)

- `PROGRESS.md` "Security & hardening": *"reset token not leaked in response"* — true for the response, but the token **is logged** (finding 4). The claim is misleadingly narrow.
- `PROGRESS.md` "Tenant-scoped identity lookups" — holds for ride/driver/rider/notification, but **not** for admin user activate/deactivate, promo codes, or admin scheduled-rides (finding 11).
- `PROGRESS.md` Now/Next still-open items that are active holes, not just nice-to-haves: *"Rate limiting on auth endpoints"* (no lockout → login/forgot-password brute-force and enumeration), *"HTTPS enforcement"*, *"Environment variable management (Secrets Manager)"* (root cause of finding 3).
- **Not tracked at all**: no CSRF strategy documented for the cookie-based BFF (CSRF is globally disabled; SameSite=Lax is the only mitigation); no session/token revocation or rotation; no dependency scanning of the committed `.next` build output.
- Doc/code drift: `ARCHITECTURE.md` says 158 tests and that `data.sql` seeds on startup; `PROGRESS.md` says 197, and `application.properties` sets `spring.sql.init.mode=never` so `data.sql` never runs (Flyway V2 is the real seeder).

## Convention violations (AGENTS.md)

- **JWT storage** — "Auth via httpOnly cookies … never localStorage for JWT": violated by storing the JWT in `sessionStorage` (`velo_ws_token`) in the rider and driver apps (finding 6). (2 files + 2 WS libs.)
- **Secured-endpoint annotations** — mostly compliant (`@PreAuthorize` present on admin/earnings/promo/tenant); no violations found beyond the missing checks in finding 1.
- **`@Transactional` import** — compliant: services use `org.springframework.transaction.annotation.Transactional` (the documented rule), and reads use `readOnly = true` where expected.
- **Response envelope** — compliant; `GlobalResponseHandler` wraps returns and excludes `/actuator`.
- **Error semantics** — `RuntimeConflictException` is reused for authentication failures ("Invalid password", permission denials) returning 409 instead of 401/403; not a rule breach but a convention smell worth a lint.
